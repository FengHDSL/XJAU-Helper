# 液态玻璃 · 内容实时折射（GLSL 自绘引擎）技术方案

> 版本：v1（2026-09-06）· 状态：方案评审稿 · 对应问题："卡片边缘扭曲折射效果缺失，现在是纯平板玻璃"

## 1. 目标与判定标准

- **目标**：在鸿蒙端还原 AndroidLiquidGlass（Kyant0）的"液态玻璃"核心视觉——玻璃覆盖下的**滚动内容在卡片边缘被逐像素折射扭曲**（SDF 驱动采样偏移），且带边缘高光与厚度感，随内容滚动实时更新。
- **判定**：滚动列表经过玻璃卡下方时，列表文字/图片在卡片内侧边缘产生**连续的拉伸/弯曲过渡**（非跳变、非静态装饰），帧率可接受（≥45fps 试点卡）。
- 与当前实现的差异：现卡片 = 均匀磨砂 + 半透明白 + 1vp 边，即"平板玻璃"；缺的是**边缘非均匀采样**。

## 2. 为什么现在是"平板玻璃"

当前实现链路（ArkUI 层）：

```
页面内容(透明/壁纸) → 卡片 Column：backgroundEffect(radius/saturation/brightness)
                         + backgroundColor(rgba 半透明白) + border(1vp 亮边)
```

`backgroundEffect` 是**均匀**的背景高斯模糊 + 调色，采样核在各像素相同；没有"按距卡片边缘距离改变采样位置"的能力，因此内容不会在边缘弯曲。AndroidLiquidGlass 的弯曲来自其 AGSL shader：

```
float sd = sdRoundedRect(centeredCoord, halfSize, radius);   // 圆角矩形距离场
if (-sd >= refractionHeight) return content.eval(coord);      // 玻璃外：原样
float d = circleMap(1.0 - -sd / refractionHeight) * refractionAmount;
float2 grad = normalize(gradSdRoundedRect(...) + depthEffect * normalize(centeredCoord));
return content.eval(coord + d * grad);                        // 按距离场偏移采样 → 边缘拉伸
```

复刻它需要**自定义像素着色器 + 可被逐像素采样的"背后内容纹理"**。

## 3. 平台能力盘点与限制

| 能力 | 类型 | 能否作为"背后内容"纹理 | 备注 |
|---|---|---|---|
| `componentSnapshot` | 同步截图→PixelMap | 部分：静态可用 | 整组件/区域截图，主线程开销大；滚动场景不可逐帧调用 |
| XComponent + EGL/GLES | 自定义渲染表面 | ✅ 唯一自绘通道 | 可离屏渲染、双缓冲、shader 自由 |
| ArkGraphics2D PixelMap/ImageFilter | 图像处理 | 模糊/变换可用，**无自定义采样 shader** | `ImageFilter` 仅内置滤镜 |
| `backgroundEffect` | 背景均匀模糊 | 不可做折射 | 逐像素不可编程 |
| `backgroundBlurStyle` | 预设磨砂 | 不可做折射 | 同上 |
| HDS `systemMaterialEffect` | HdsTabs 悬浮栏 | 不可做折射 | 材质只能挂底栏/悬浮层 |

**平台级限制（B 路线的前提）**：应用无法以流式方式读取"自己渲染树其它层"作为纹理（无系统 backdrop API）。要让滚动内容被逐像素折射，**唯一路径是把被玻璃覆盖的内容从普通组件树迁入我们自己的离屏渲染管线**，使其内容天然是一张纹理。

## 4. 核心架构：内容 → 离屏纹理 → GL 折射合成

```
┌────────────────────────────────────────────────────────┐
│  ArkUI 层（页面骨架、顶栏、卡片排版、按钮、其余区域）        │
│  ┌──────────────────────────────────────────────────┐  │
│  │  XComponent（玻璃渲染区，覆盖卡片几何）              │  │
│  │  帧管线：                                           │  │
│  │   ① 内容源提交：                                   │  │
│  │       S1 壁纸/静态背景 → 纹理（一次性上传）            │  │
│  │       S2 滚动内容 → 离屏重绘为 texture（每帧更新）      │  │
│  │   ② 折射 Pass：RoundedRectRefraction(Dispersion)    │  │
│  │       uniform: size/cornerRadii/refractionHeight/    │  │
│  │               refractionAmount/depthEffect/content    │  │
│  │   ③ 高光/厚度 Pass（边缘方向光 + 内暗缘）              │  │
│  │   ④ 输出到屏幕（玻璃卡下方图像被渲染为该区内容）         │  │
│  └──────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────┘
```

### 4.1 内容源方案（决定"实时"能否成立）

- **S1 壁纸/静态**：一次 `componentSnapshot`/直接加载壁纸 → 上传 GL 纹理。内容不动，纹理不更新。
- **S2 滚动内容（B 目标的核心）**：把玻璃区背后的内容"改为由引擎绘制"：
  - 玻璃覆盖范围对应的内容列表，其**可视片段内容以 texture 形式**由 ArkUI 侧每帧（或滚动静止时）提供——落地点是用 `componentSnapshot` 同步抓玻璃区所在窗口再裁剪（滚动中性能不可行），因此工程化取舍为：
  - **区域自绘化**：玻璃区不再放普通 `Scroll/List`，而是把该区域内容渲染进离屏 FBO：列表绘制命令（文本/图片矩形摆放）由引擎绘制 → texture 自带滚动内容 → shader 采样折射 → 输出。
  - 由此，滚动内容与折射**同帧**，任意像素可弯，实时成立。

### 4.3 AGSL → GLSL 直译要点

- `uniform shader content` → `uniform sampler2D uContent`；
- `content.eval(coord)` → `texture(uContent, uv)`；
- SDF / `gradSdRoundedRect` / `circleMap` 原样保留；
- dispersion 七通道多次采样合并按原文（r/g/b/a 权重保留）；
- 高光 pass 输出在折射 pass 之上做加法混合（`hdsMaterial` 不可用，此为主观光效）。

### 4.4 滚动场景数据流（B 目标）

```
用户滚动
  → ArkUI onScrollIndex/offset（事件节流）
  → native 更新"当前可视内容"到离屏 FBO（增量重绘：新行绘制、回收行）
  → refraction pass 每帧读取 FBO 纹理 → 玻璃渲染区显示扭曲结果
```

## 5. 里程碑与工作量（粗评）

| 里程碑 | 内容 | 主要风险 | 相对工作量 |
|---|---|---|---|
| M0 | native 空库 + XComponent 显示纯色/纹理 | CMake/NAPI 链路、EGL 上下文 | 中 |
| M1 | S1（静态壁纸纹理）真折射 Demo：单卡 | shader 直译正确性、UV/坐标 | 中 |
| M2 | S2：一张**滚动列表玻璃卡**（区域自绘化） | 滚动内容重绘性能、文字离屏渲染（需 Raster 文本路径或 PixelMap 截字） | 高 |
| M3 | 与现有沉浸光感开关/滑杆参数贯通 | 参数热更新 | 低 |
| M4 | 主界面卡片逐步替换 | 页面回归、内存/纹理上限 | 高 |

> 注意：M2 的"文字离屏渲染"是最大难点——ArkUI 不允许把文字绘制进自定义离屏 FBO；可行的折中：文字所在区域用逐行 `componentSnapshot`（静态行级）合成滚动画面纹理（滚动时按行替换），像素级实现在文字部分为"行级刷新"，图片/背景可真正连续。

## 6. 风险与取舍

1. **文字实时弯曲**：原生级逐像素渲染文字不可用；工程上需"行级纹理拼接"折中，弯曲主要在行间过渡近似，效果打折但远好于平板。
2. **性能**：离屏 FBO 分辨率 = 玻璃区 ×dpr；需 mipmap/降采样控制。
3. **回归成本**：玻璃区内容自绘化后，原有组件能力（无障碍/点击/系统滚动优化）需自行承担。
4. **替代性建议**：若目标是系统级"液体玻璃"观感，等待鸿蒙开放 backdrop 可编程采样后再做，可获得更彻底的实时性与低成本。

## 7. 结论与建议

- B（内容实时折射）技术上可行，本质是**把玻璃区建成一个轻量自绘渲染引擎（内容+折射+高光同帧）**；工程成本高，尤其文字离屏渲染需行级折中。
- 建议先行 **M1（静态/壁纸源真折射）** 验证 GLSL 直译与 EGL 链路，此步成本可控且能立刻让"卡片边缘扭曲"出现；M2 滚动内容实时化视 M1 表现与用户接受度再启动。
- 本次会话暂不展开 native 代码开发，待本方案评审确认后立项。
